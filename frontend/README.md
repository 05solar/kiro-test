# frontend

「내일까지 해야 하는데」 프론트엔드. Next.js 16 (App Router) + React 19 + Tailwind 4 + zustand.

백엔드와 연결되어 있다. 화면에 보이는 학습 주제·계획·퀴즈는 전부 서버가 만든 실제 값이다.

## 실행

```bash
npm install
npm run dev        # http://localhost:3000
```

백엔드가 함께 떠 있어야 한다.

```bash
cd ../backend && ./gradlew bootRun    # http://localhost:8080
```

| 명령 | 하는 일 |
| --- | --- |
| `npm run dev` | 개발 서버 |
| `npm test` | Vitest. AI를 부르지 않아 무료다 |
| `npm run build` | 프로덕션 빌드 |
| `npx tsc --noEmit` | 타입 검사 |

## 백엔드와 어떻게 연결되는가

### CORS 대신 프록시

브라우저는 항상 같은 오리진(`/api/...`)을 부르고, 실제 전달은 Next 서버가 한다.

```
브라우저 ──▶ :3000/api/sessions ──▶ :8080/api/sessions
             (같은 오리진)          (next.config.ts rewrite)
```

포트가 다르면 브라우저가 직접 부를 때 preflight부터 막힌다.
백엔드 주소는 `BACKEND_URL` 환경변수로 바꾼다. `NEXT_PUBLIC_` 을 붙이지 않는다 —
서버에서만 쓰므로 브라우저 번들에 내부 주소가 들어갈 이유가 없다.

### 구조

```
lib/api/
├── types.ts    백엔드 응답 타입. 변환 로직을 넣지 않는다
├── client.ts   모든 요청이 지나는 유일한 통로. 에러 처리도 여기
├── index.ts    엔드포인트 하나당 함수 하나
└── adapt.ts    백엔드 응답 → 화면 타입. 두 시스템의 접합면

app/_components/
├── session-store.ts    8자리 세션 코드 (localStorage)
├── use-session.ts      서버에서 세션(과목·범위·근거)을 읽는다
└── use-curriculum.ts   서버에서 계획과 진행 상태를 읽는다
```

화면 컴포넌트는 백엔드 DTO를 직접 모른다. 서버 계약이 바뀌면 `adapt.ts` 만 고친다.

## 계획과 진행 상태는 서버가 갖는다

`lib/curriculum.ts` 의 `generateCurriculum()` 은 **실제 데이터에 쓰지 않는다.**
백엔드에 같은 일을 하는 계획기가 있고, 둘 다 계산하면 화면에 보이는 남은 시간과
서버가 아는 값이 어긋난다. 그때 어느 쪽이 맞는지 판단할 근거가 없다.

완료한 단계도 마찬가지다. 서버에서 읽는다. 다른 기기에서 8자리 코드만 넣으면
그대로 이어지는 것이 이 서비스의 핵심이라, 화면이 따로 들고 있으면 안 된다.

localStorage에 남기는 것은 두 가지뿐이다.

```
세션 코드      서버에 물어보기 전에 알아야 한다
weakSteps      사용자가 직접 표시한 값. 백엔드에 대응하는 개념이 없다
```

## 자료가 없어도 진행된다

강의자료 업로드는 **선택**이다. 올리지 않으면 서버가 과목명과 시험 범위만 보고
일반적인 교과 지식으로 주제·계획·퀴즈를 만든다. 그래서 `/upload` 에서 자료 없이
넘어갈 수 있지만, 시험 범위마저 비어 있으면 만들 근거가 없으므로 막는다.

그렇게 만든 내용은 실제 수업 범위와 다를 수 있다. 감추면 사용자가 자기 강의자료에서
뽑은 내용이라고 믿게 되므로, 커리큘럼·퀴즈 화면에 근거를 항상 표시한다.

```
sourceType = USER_MATERIAL      →  [📚 학습자료 기반]
sourceType = GENERAL_KNOWLEDGE  →  [💡 일반 지식 기반] + 안내 문구
sourceType = null (분석 전)      →  아무것도 그리지 않는다
```

표시 규칙은 `lib/api/adapt.ts` 의 `toSourceLabel()` 한 곳에 있고, 문구가 조용히
사라지지 않도록 테스트로 못박아 두었다.

## 퀴즈 채점은 서버가 한다

퀴즈 조회 응답에 **정답이 없다.** 내려보내면 개발자 도구로 다 보인다.
답안을 제출하면 그 응답으로 정오답과 해설이 온다.

## AI를 부르는 화면

누를 때마다 과금된다.

```
/analysis          자료 분석 + 계획 생성
/quiz/[stepId]     퀴즈 생성 (이미 있으면 재사용)
```

같은 세션에서 다시 눌러도 서버가 기존 결과를 돌려주므로 중복 과금되지 않는다.
개발 모드는 effect를 두 번 실행하므로 `useRef` 가드로 한 번만 부르게 막아 두었다.

## 테스트

```bash
npm test
```

API 클라이언트와 어댑터만 테스트한다. 이 둘이 백엔드와 화면 사이의 접합면이고,
여기가 어긋나면 예외 없이 조용히 틀린 화면이 나온다.

`fetch` 를 갈아 끼워 실제 네트워크를 부르지 않는다. **AI 호출은 자동 테스트에 넣지 않는다.**

과정과 결과는 `../docs/frontend-integration-test.md` 에 있다.

## 알려진 제약

- **맵 노드가 7칸 고정이다.** `lib/mapNodes.ts` 좌표가 하드코딩이라 서버가 8단계 이상을 주면
  맵에 안 나온다. 오른쪽 STEP 목록에는 나온다.
- **결과 화면에 정답을 보여주지 못한다.** 정답 번호가 답안 제출 응답에만 있고
  채점 결과 조회에는 없다. 백엔드 응답에 `correctIndex` 가 추가되면 해결된다.
