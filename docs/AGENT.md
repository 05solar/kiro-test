# docs — 에이전트 작업 규칙

## 원칙

이 폴더의 문서는 **구현된 사실**만 담는다. 계획은 "예정"으로만 표시한다.
구현보다 앞선 문서는 읽는 사람을 잘못된 방향으로 보낸다.

## 지킬 것

- 실제 호출 결과, 실제 스키마 덤프를 근거로 쓴다.
- 표와 예시를 함께 고친다. 한쪽만 고치면 어긋난다.
- 미구현은 "미구현 (TODO)"로 명시한다.
- 판단이 필요했던 지점(명세 모순, 트레이드오프)은 근거와 함께 남긴다.
  나중에 같은 고민을 반복하지 않기 위해서다.

## 하지 말 것

- 기획 원문을 그대로 복사해 넣기 (원문은 별도 관리한다)
- 구현하지 않은 API의 상세 명세 작성
- 내부 구현 세부(클래스명, 메서드 시그니처)를 API 명세에 노출
- 문서만 고치고 코드를 그대로 두기, 또는 그 반대

## 문체

- 한국어로 쓴다. 기술 용어는 원어를 그대로 쓴다(예: `sessionCode`, `Clock`).
- 단정적으로 쓴다. "~할 수도 있다" 대신 "~한다".
- 표와 코드 블록을 적극적으로 쓴다. 긴 문단으로 설명하지 않는다.
