# 학습 챗봇 — 검증 기록

공부하다 막힌 것을 그 자리에서 물어보는 기능을 확인한 기록이다.

- 대상: 2단계(학습자료 기반 학습 챗봇)
- 환경: `docker compose` (db + backend + frontend), `PUBLIC_PORT=8090`
- **AI 모드: `LLM_MODE=mock`** — 실제 Gemini 를 부르지 않는다. 챗봇은 이 프로젝트에서
  가장 자주 눌리는 기능이라, 확인 한 번에 질문 서너 개가 나간다. 실제 AI 호출 검증은
  마지막에 최소 횟수만 따로 한다.

## 무엇을 확인하는가

이 기능은 "답이 오는 것"만으로는 부족하다. **무엇에 근거해 답했는지를 사실대로 말하는지**가
같은 무게로 중요하다. 자료를 올린 사람은 답변이 자기 강의자료에서 나왔다고 믿기 때문이다.

| | 확인 대상 |
| --- | --- |
| A | 자료 기반 세션 — 답하고, 근거를 사실대로 표시하고, 대화가 남는다 |
| B | 자료가 없는 세션 — 답하되 자료 기반이라고 하지 않는다 |
| C | 입력 제한과 세션 경계 |

## 검증 절차

### 사전 준비 — 스키마 적용

운영 프로파일은 `ddl-auto=validate` 다. 테이블이 늘었으므로 새 이미지를 올리기 **전에**
마이그레이션을 먼저 적용한다.

```bash
docker compose exec -T db psql -U postgres -d naeil_study < docs/migrations/002-study-chat.sql
LLM_MODE=mock QUIZ_AI_MODE=mock PUBLIC_PORT=8090 docker compose up -d --build
```

### 실행

```bash
bash scripts/chat-verify.sh
```

요청은 전부 프론트엔드의 `/api` 프록시(`localhost:8090`)를 지난다. 백엔드 포트를 밖으로
열지 않으므로, 실제 사용자가 지나는 경로와 같은 경로로 확인하게 된다.

## 결과 — 19건 전부 통과

```

  세션: RLUXSC7A
  [PASS] A1 분석 전에는 409 — 답할 근거가 없다
  [PASS] A2 code=CHAT_NOT_READY
  [PASS] A3 분석 후에는 답한다 (200)
  [PASS] A4 자료 기반으로 표시된다
  [PASS] A5 자료에서 근거를 찾았다고 표시한다
  답변: "[목 응답입니다. 실제 AI 답변이 아닙니다.]\n질문: 교착상태 조건이 뭐야?
         \n근거: 올려주신 강의자료 160자 구간\n지난 대화 0줄을 함께 보고 답하는 자리입니다."
  [PASS] A6 자료 밖 질문은 자료 기반이 아니라고 알린다
  [PASS] A7 대화가 그대로 저장돼 다시 읽힌다 (4줄)
  [PASS] A8 질문이 남아 있다

== C. 입력과 접근 제한 ==
  [PASS] C1 빈 질문은 400
  [PASS] C2 1000자를 넘는 질문은 400
  [PASS] C3 없는 세션의 대화는 404
  [PASS] C4 code=SESSION_NOT_FOUND
  [PASS] C5 내 대화는 내 세션에만 있다
```

### A5 와 A6 이 이 검증의 핵심이다

같은 세션에 두 질문을 던진다.

```
"교착상태 조건이 뭐야?"          → answeredFromMaterial: true   (자료에 있다)
"블록체인 합의 알고리즘 설명해줘"  → answeredFromMaterial: false  (자료에 없다)
```

두 번째 질문에서도 `grounded` 는 여전히 `true` 다 — 이 **세션**은 자료 기반이다.
바뀌는 것은 `answeredFromMaterial`, 즉 이 **답변**이 자료에서 나왔는지다.
화면은 이때 "자료에서 근거를 찾지 못해 일반적인 교과 지식으로 답했다"를 띄운다.

목 응답 본문의 `근거: 올려주신 강의자료 160자 구간` 은 `StudyContextProvider` 가 실제로
문단을 골라 넘겼다는 뜻이다. 전체 자료(약 200자 중 관련 문단만)를 통째로 넘기지 않았다.

### C6 을 확인하는 방법

자료 기반 세션(A)에서 "교착상태"를 물었고, 자료 없는 세션(B)에서 "스택"을 물었다.
B 의 대화 조회에 "교착상태"가 나타나지 않는지를 본다. 세션 경계가 새면 남의 시험 범위와
약점이 그대로 보인다.

## 자동 테스트

수동 검증과 별개로 아래가 회귀를 막는다. **어느 것도 실제 AI 를 부르지 않는다**(`FakeAiChatClient`).

| 계층 | 건수 | 내용 |
| --- | --- | --- |
| `ChatServiceTest` | 11 | 저장 시점, 빈 답 거절, 근거 표시 세 갈래, 대화 순서·개수 |
| `SimpleStudyContextProviderTest` | 6 | 관련 문단만 고르는지, 못 찾으면 비우는지, 자료 없는 세션은 문서를 읽지도 않는지 |
| `ChatControllerTest` | 8 | 상태 코드와 응답 형태, 내부 사유 비노출 |
| `ChatApiIntegrationTest` | 6 | 실제 HTTP + DB. 긴 한글 왕복, 대화 복구, 세션 경계 |

전체 백엔드 테스트 **903건 통과**.

### 특히 못박아 둔 것

```java
// 자료가 없는 세션은 AI 가 뭐라 답하든 자료 기반이 아니다
aiChatClient.respondWith(request -> new AiChatAnswer("자료에 따르면...", true));
assertThat(response.answeredFromMaterial()).isFalse();
```

모델이 규칙을 어기는 것은 언제든 일어난다. 그때 서버가 마지막으로 걸러 내지 않으면
"올리지도 않은 자료에 따르면"이라는 답이 그대로 나간다.

## 설계에서 고른 것

| 갈림길 | 고른 쪽 | 이유 |
| --- | --- | --- |
| 경로 | `/api/sessions/{code}/chat` | 기획 초안은 `/api/chat/study` 였다. 세션 아래에 두면 다른 모든 엔드포인트와 같은 소유권 검사를 지난다 |
| 대화 기록 | 서버 저장 | 8자리 코드로 이어져야 하고, 클라이언트가 보내오면 없던 발화를 지어낼 수 있다 |
| 지난 대화 전달 | `<conversation>` 태그 안 | SDK 멀티턴 자리에 넣으면 저장된 대화가 "실제 발화"로 취급되어 주입 여지가 커진다 |
| 컨텍스트 추출 | 챗봇 전용 구현 | 퀴즈는 Topic 기준으로 넓게, 챗봇은 질문 기준으로 좁게. 기준이 다르다 |
| 저장 시점 | 성공했을 때 한 쌍으로 | 질문만 남으면 다음 프롬프트에 "답하지 않은 질문"이 섞인다 |

## 실제 AI 로도 확인했다

**실제 Gemini 호출 검증은 따로 마쳤다** — `live-gemini-test.md`.
같은 질문에 자료 있는 세션과 없는 세션이 다르게 답했고, 자료 있는 쪽은 자료의 용어를
그대로 썼다("순환 대기"가 아니라 "환형 대기").
