# 문서 관리 절차

## 언제 문서를 고치는가

| 변경 | 고칠 문서 |
| --- | --- |
| API 추가 / 응답 필드 변경 | `api/{도메인}-api.md`, `api/README.md` 현황 표 |
| 새 에러 코드 | `api/error-codes.md` |
| 엔티티 필드 / 테이블 변경 | `database.md` |
| STEP 완료 | `../PROCESS.md` 검증 기록, `../README.md` 진행 상태 표 |
| 새 폴더 추가 | 그 폴더의 `README.md` / `PROCESS.md` / `AGENT.md` |
| 명세 모순 발견 | `../AGENT.md` 의 "명세 모순" 목록 |

코드와 문서는 같은 커밋에서 고친다. "나중에 문서 정리"는 하지 않는다.

## 문서 작성 순서

```
1. 무엇이 바뀌었는지 한 줄로 적는다
2. 그 변화가 호출하는 쪽에 보이는가?  → api/
3. 저장 구조가 바뀌었는가?            → database.md
4. 개발 순서/검증에 영향이 있는가?    → ../PROCESS.md
5. 다음 사람이 실수할 만한 지점인가?  → ../AGENT.md
```

## 검증

문서를 고친 뒤에는 다음을 확인한다.

- 문서에 적힌 명령을 그대로 실행했을 때 동작하는가
- 문서에 적힌 응답 예시가 실제 응답과 같은가
- 링크가 깨지지 않았는가
