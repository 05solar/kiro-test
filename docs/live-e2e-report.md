# 라이브 E2E 종합 리포트 — 실제 Gemini API × 실제 강의자료 3회

2026-08-27 실행. 실제 Gemini API 키와 실제 강의 PDF 로 백엔드 전체 플로우를 3회 구동했다.
회차별 상세 과정은 [run 1](live-e2e-run1.md) · [run 2](live-e2e-run2.md) · [run 3](live-e2e-run3.md) 참고.

각 회차가 검증한 전체 플로우:

```
세션 생성 → 시험 정보(6시간 후, 180분) → PDF 업로드 → PDFBox 텍스트 추출
  → Gemini 분석(Topic 생성) → 규칙 기반 학습 계획 → STEP 1 시작/완료 + 동적 재조정
  → Gemini 퀴즈 생성(정답 미노출 확인) → 답안 제출/서버 채점 → 점수 집계
  → Gemini 오답 복습 요약 생성 → 조회 복구 → 캐시 재사용 확인
```

- 답안은 보기 0,1,2,3,0 순서의 기계적 선택이라 점수가 낮은 것이 정상이다(정답 위치는 AI가 분산).
- 퀴즈 문제 응답에 `correctIndex` / `explanation` 이 없음을 매 회차 검증했다.
- 오답 요약은 오답 Topic 만 담았고, 조회로 복구되며, 답안 변화가 없으면 재요청 시 AI 를 다시 부르지 않았다.

## 실행 환경

| 항목 | 값 |
| --- | --- |
| DB | PostgreSQL 16 (Docker, 포트 55432) — H2 아님 |
| AI | Gemini REST `generateContent`, 모델 `gemini-3.5-flash-lite` |
| 실행 방법 | `LiveGeminiFullFlowE2ETest` (환경변수 `GEMINI_API_KEY`, `E2E_DOC_DIRS` 있을 때만 활성) |
| 키 취급 | 셸 환경변수로만 주입. 저장소 파일·리포트에 미기록 |

## 시도 이력 — 완주까지 잡은 문제 6건

실패도 기록한다. 각 문제는 코드에 반영되어 재발하지 않는다.

| # | 증상 | 원인 | 조치 |
| --- | --- | --- | --- |
| 1 | 업로드에서 연결 강제 종료 | 테스트 환경의 multipart 기본 제한(파일당 1MB) < 실제 PDF 크기 | E2E 속성으로 운영과 같은 20MB/100MB 지정 |
| 2 | "api-key not configured" | 테스트 application.yml 이 메인 yml 을 대체해 `GEMINI_API_KEY` 매핑 소실 | E2E 속성에서 환경변수 매핑 재연결 |
| 3 | 분석 502 (429 반복) | 무료 티어 분당 한도. 초 단위 백오프로는 다음 1분 창 못 미침 | 429 전용 백오프 15초×시도, 청크 3만 자로 호출 수 축소 |
| 4 | 클라이언트가 먼저 끊음 (Read timed out) | 429 대기 동안 테스트 HTTP 읽기 타임아웃(~3분) 초과 | 테스트 읽기 타임아웃 30분으로 상향 |
| 5 | "unparsable json" 간헐 실패 | ① thinking 모델의 `thought` 파트가 본문에 섞임 ② 모델이 `{"topics":[...]}` 대신 최상위 배열로 응답 | ① thought 파트 제외 ② 단일 필드 레코드는 배열을 감싸 복구 |
| 6 | 퀴즈 검증 실패 (형식 위반) | 생성이 확률적이라 가끔 문항 수·보기 규칙 위반 | 검증 실패 시 1회만 재요청 (비용 상한 유지) |

모델 한도 이력: `gemini-3-flash-preview` → 무료 한도 소진(429), `gemini-3.6-flash` → 성공 2회 후 한도 소진,
`gemini-3.5-flash-lite` 로 3/3 완주. 모델별 한도가 분리되어 있다.

## 눈여겨볼 관찰

- **동적 재조정(STEP 9)이 매 회차 동작** — STEP 1 완료 직후 `reallocation.changed=true`,
  남은 PENDING 단계가 원래 권장 시간 방향으로 복구되었다(압축됐던 계획 + 실제 학습 0~1분).
- **Grounding 확인** — 분석 Topic·퀴즈·오답 요약 모두 업로드한 강의자료의 실제 용어로 구성됐다
  (예: run 3 포인터/연결리스트/트리).
- **개선 여지** — run 2 퀴즈 문면에 프롬프트 태그명(`<lecture_context>`)이 노출됐다.
  채점에는 지장이 없지만, 태그명을 언급하지 말라는 지시를 프롬프트에 추가할 만하다.
- run 2는 근거가 좁아 AI 가 5문제 대신 3문제를 만들었다 — 허용 범위(3~5) 내 정상 동작.

## 회귀 확인

라이브 E2E 는 환경변수가 없으면 스킵되므로 기본 스위트는 영향이 없다.
전체 스위트와 빌드는 push 직전에 다시 확인했다 (`./gradlew test`, `clean build`).
