# API 문서 — 에이전트 작업 규칙

## 이 폴더의 역할

프론트엔드 개발자가 백엔드 코드를 열어보지 않고도 연동할 수 있게 하는 것이 목적이다.
따라서 "구현이 이렇게 되어 있다"가 아니라 "이렇게 호출하면 이렇게 응답한다"를 적는다.

## 지킬 것

- 응답 예시는 실제 호출 결과를 붙인다. 추측한 JSON을 쓰지 않는다.
- 필드를 추가하면 **필드 표와 예시 JSON을 함께** 고친다. 하나만 고치면 반드시 어긋난다.
- 값이 없는 필드는 키를 생략하지 않고 `null`로 표기한다. 실제 응답이 그렇기 때문이다.
- 미구현 항목은 "미구현 (TODO)"로 명시한다. 구현된 것처럼 적지 않는다.
- 보안 관련 정책(코드 노출, 레이트리밋)은 구현 여부를 표로 관리한다.

## 하지 말 것

- 구현되지 않은 API의 상세 명세 작성
- 내부 UUID, 테이블명, 예외 클래스명을 응답 명세에 노출
- 에러 메시지를 문서에서 임의로 바꾸기 (`ErrorCode`가 정본이다)
- 한 문서에 여러 도메인의 API를 섞기 — 도메인마다 파일을 나눈다

## 파일 이름 규칙

```
{도메인}-api.md      예: session-api.md, document-api.md, quiz-api.md
error-codes.md       공통 에러 (도메인별로 나누지 않는다)
```
