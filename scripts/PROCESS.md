# scripts — 작업 절차

## 스크립트를 추가할 때

1. **자동 테스트로 옮길 수 있는지 먼저 본다.** JVM 안에서 검증할 수 있는 것은
   여기 두지 않는다. 여기 두는 것은 컨테이너·프록시·스키마처럼 밖에 있는 것들뿐이다.
2. 실제 AI 를 부르지 않는다. `LLM_MODE=mock` 을 전제로 쓴다.
3. 통과/실패를 사람이 세지 않아도 되게 `[PASS]`/`[FAIL]` 과 합계를 찍는다.
4. `README.md` 표에 한 줄 추가한다.
5. 실행 결과는 `docs/` 아래 md 파일로 남긴다. 스크립트만 두고 결과를 남기지 않으면
   "언제 무엇이 통과했는지"가 사라진다.

## Windows(Git Bash)에서 걸리는 것

두 번 다 실제로 걸렸다. 새 스크립트에서도 같은 방식으로 피한다.

| 증상 | 원인 | 대응 |
| --- | --- | --- |
| `400 INVALID_REQUEST` | 한글 본문을 셸 인자로 넘기면 콘솔 코드페이지에서 깨진다 | UTF-8 파일로 쓰고 `--data-binary @file` |
| `curl: (26)` | mingw curl 이 `-F "@/tmp/..."` 를 열지 못한다 | 작업 디렉터리를 Windows 경로로 (`pwd -W`) |

## 검사 함수에서 하지 말 것

설명 문자열 안에서 명령 치환을 쓰지 않는다.

```bash
grep -q 200 code; check "... ($(cat code))" $?   # $? 가 cat 의 것으로 덮인다
```

인자를 만들면서 실행되는 `$(...)` 가 `$?` 를 덮어써서, 실패한 검사가 통과로 찍힌다.
값이 필요하면 먼저 변수에 담는다.
