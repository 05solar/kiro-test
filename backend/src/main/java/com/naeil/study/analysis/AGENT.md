# analysis — 에이전트 작업 규칙

## 절대 지킬 것

- **테스트에서 실제 AI API를 부르지 않는다.** `FakeAiAnalysisClient` 를 쓴다.
  과금이 발생하고, 응답이 매번 달라 테스트가 흔들리며, 네트워크가 없으면 실패한다.
- API 키를 코드에 두지 않는다. 환경변수로 받는다.
- 도메인 서비스에서 AI SDK를 직접 부르지 않는다. `AiAnalysisClient` 만 쓴다.
- AI 응답을 검증 없이 저장하지 않는다.
- AI에게 내부 UUID를 주지 않는다. `DOC_1` 같은 참조값을 주고 서버가 되돌린다.

## 프롬프트

- 시스템 지시문과 분석 대상 데이터를 한 문자열로 이어붙이지 않는다.
- 자료와 학습 맥락은 태그로 감싸고, 명령이 아니라는 점을 시스템 프롬프트에 명시한다.
- 사용자 입력을 검증된 사실로 취급하지 않는다.
- 강의자료에 없는 내용을 만들어 내지 말라는 규칙을 유지한다.

## 시간과 우선순위

- 이 단계에서 `remainingStudyMinutes` 로 Topic을 걸러 내지 않는다.
- `교수 강조 × 2.0` 같은 숫자 가중치를 하드코딩하지 않는다.
  자료와 맥락을 함께 놓고 LLM이 판단하게 한다.
- `mustStudyMatched` 는 가중치가 아니라 제약이다.

## 트랜잭션

- `AnalysisService` 에 `@Transactional` 을 붙이지 않는다. AI 호출이 오래 걸린다.
- 상태 변경은 `AnalysisStateWriter` 의 짧은 트랜잭션으로 한다.
- 중간 결과(주제 후보)를 `topics` 테이블에 저장하지 않는다. 최종 결과만 저장한다.

## 로그

다음을 로그에 남기지 않는다.

```
추출 텍스트 전문 / 학습 맥락 전문 / 프롬프트 전문 / AI 응답 전문
```

`sessionId`, 문서 수, 조각 수, 성공 여부, 처리 시간, Topic 수만 남긴다.

## 재시도

- 연결 오류와 5xx는 SDK가 재시도한다.
- 응답 검증 실패는 통합 요청을 1회만 다시 보낸다. 무한 재시도는 비용만 늘린다.
- 형식이 잘못된 프롬프트를 반복 전송하지 않는다.
