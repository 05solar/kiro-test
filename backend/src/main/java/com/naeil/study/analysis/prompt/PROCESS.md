# analysis/prompt 작업 절차

## 프롬프트를 고칠 때

```
1. 영역 구분을 유지한다 (SYSTEM RULES / TASK / 데이터)
2. 자료와 학습 맥락은 태그로 감싼 채로 둔다
3. 판단 기준(importance, estimatedStudyMinutes)을 바꾸면 문서도 함께 고친다
4. 실제 자료로 수동 확인한다
```

프롬프트 품질은 자동 테스트로 잡히지 않는다. 형식이 맞는 응답이 와도 내용이 나빠질 수 있다.
문구를 바꾼 뒤에는 실제 강의자료 몇 개로 결과를 눈으로 본다.

## 필드를 추가할 때

```
1. 응답 record 에 필드 + @JsonPropertyDescription
2. 통합 프롬프트에 판단 기준을 적는다
3. 검증기에 규칙을 추가한다
```

record만 고치면 AI는 그 필드를 왜 채워야 하는지 모른다.

## 검증

프롬프트 자체의 단위 테스트는 두지 않는다. 문자열 비교는 문구를 다듬을 때마다 깨지고
품질을 보장하지도 않는다. 대신 서비스 테스트에서 프롬프트에 들어간 값
(과목, 학습 맥락, 문서 참조)을 확인한다.

```bash
./gradlew test --tests "*AnalysisServiceTest*"
```
