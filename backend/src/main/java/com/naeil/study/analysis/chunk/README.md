# analysis/chunk

문서 텍스트를 AI에 보낼 크기로 나눈다.

| 클래스 | 역할 |
| --- | --- |
| `DocumentChunker` | 조각 나누기 |
| `DocumentChunk` | 조각 하나 (문서 ID, 파일명, 순번, 텍스트) |

## 왜 나누는가

여러 문서의 텍스트를 한 문자열로 붙여 한 번에 보내면 모델의 컨텍스트 한도를 넘긴다.
문서마다 따로 나누고, 어느 문서의 몇 번째 조각인지 함께 들고 다닌다.

## 문단 경계를 우선한다

정해진 글자 수에서 그냥 자르면 문장이 중간에 끊겨 분석 품질이 떨어진다.

```
목표 크기 근처에서
  빈 줄(\n\n) → 줄바꿈(\n) → 공백 순으로 끊을 자리를 찾는다
  못 찾으면 글자 수로 자른다 (표나 코드처럼 줄바꿈이 없는 구간)
```

완전한 의미 단위 분할(Semantic Chunking)까지 하지 않는다. MVP 범위가 아니다.

## 토큰이 아니라 글자 수

특정 모델의 토크나이저에 코드가 묶이지 않게 하기 위해서다.
모델을 바꿔도 이 클래스는 그대로 쓴다.

## 설정

```yaml
ai:
  analysis:
    chunk-size: 8000      # 글자 수
    chunk-overlap: 300    # 겹침
```

겹침을 두는 이유는 경계에서 끊긴 문장이 다음 조각 앞부분에 다시 나오게 해서
문맥이 끊기지 않게 하기 위해서다. 너무 크게 잡으면 같은 내용을 두 번 분석해 비용이 는다.

숫자를 코드에 흩어 놓지 않는다. 잘못된 값은 기동 시점에 막는다.
