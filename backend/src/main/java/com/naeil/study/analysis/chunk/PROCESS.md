# analysis/chunk 작업 절차

## 나누는 규칙을 바꿀 때

```
1. 진행이 항상 앞으로 나아가는지 확인한다 (겹침이 크면 무한 루프가 된다)
2. DocumentChunkerTest 에 경계 케이스를 추가한다
   - 짧은 문서 / 긴 문서 / 줄바꿈 없는 문서 / 빈 문서
   - 겹침이 조각 크기에 가까운 경우
3. docs/api/analysis-api.md 의 조각 설명을 갱신한다
```

## 크기를 바꿀 때

설정값만 바꾼다. 모델의 컨텍스트 한도, 비용, 분석 품질이 함께 움직인다.

```
크게  호출 수가 줄어 비용이 낮아지지만 조각 하나가 다루는 범위가 넓어져 주제가 뭉뚱그려진다
작게  주제가 세밀해지지만 호출 수와 중복 후보가 늘어난다
```
