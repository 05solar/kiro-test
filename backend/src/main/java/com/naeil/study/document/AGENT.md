# document — 에이전트 작업 규칙

## 절대 지킬 것

- 사용자가 올린 파일명을 **저장 경로에 쓰지 않는다.** 표시용 메타데이터로만 쓴다.
- 문서 조회는 항상 세션 ID를 함께 조건으로 건다.
  `findById` 로 가져와서 소유자를 비교하는 코드를 쓰지 않는다.
- 다른 세션의 문서 요청은 403이 아니라 404로 응답한다.
- 응답에 `storagePath`, `storedFileName` 을 넣지 않는다.
- 파일 내용이나 바이너리를 로그에 남기지 않는다.

## 업로드 처리

- 모든 파일을 먼저 검증하고 나서 저장을 시작한다. 하나씩 검증하며 저장하지 않는다.
- Storage 저장과 DB 저장 사이의 실패는 보상 삭제로 처리한다.
- DB 저장은 `saveAllAndFlush` 를 쓴다. 커밋 시점에 실패하면 보상 삭제를 할 수 없다.
- 보상 삭제가 실패해도 원래 예외를 덮지 않는다. 삭제 실패는 로그로 남긴다.

## 삭제 처리

- DB를 먼저 지우고 Storage를 지운다.
  반대 순서라면 DB 삭제 실패 시 **파일 없는 메타데이터**가 남는다.
  지금 순서에서는 최악의 경우 참조되지 않는 파일만 남고, 세션 만료 시 함께 정리된다.

## 세션 접근

- 세션은 `SessionService` 를 통해서만 가져온다. `StudySessionRepository` 를 직접 쓰지 않는다.
- 업로드/목록/삭제 모두 세션 활동이므로 접근시각이 갱신된다.
