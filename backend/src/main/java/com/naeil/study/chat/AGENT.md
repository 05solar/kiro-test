# chat — AI 에이전트 작업 규칙

## 절대 하지 말 것

- **테스트에서 실제 AI 를 부르지 않는다.** `FakeAiChatClient` 를 쓴다. 과금되고,
  응답이 매번 달라 테스트가 흔들리며, 네트워크가 없으면 실패한다.
- **`chat.ai-mode` 의 기본값을 `gemini` 로 바꾸지 않는다.** 챗봇은 이 프로젝트에서
  가장 자주 눌리는 기능이다. 화면을 한 번 확인하는 동안 질문을 서너 개 던지게 된다.
- **질문·답변 본문을 로그에 남기지 않는다.** 사용자가 약점을 그대로 적는 자리다.
- **대화 기록을 요청 본문으로 받지 않는다.** 없던 발화를 지어내 프롬프트에 넣을 수 있다.
- **`answeredFromMaterial` 을 모델 응답 그대로 내보내지 않는다.** 자료가 없는 세션에서는
  무조건 false 다. 서버가 마지막으로 판단한다.
- API 키를 코드에 두지 않는다. 환경변수로만 받는다.

## 판단이 필요할 때

- **답할 근거가 없으면 답하지 않는다.** 분석 전 세션은 409 다. 그럴듯한 일반 상식을
  내보내면 사용자는 그것을 자기 시험 범위의 내용으로 받아들인다.
- **모르면 모른다고 답하게 한다.** 프롬프트의 근거 규칙을 느슨하게 고치지 않는다.
- 자료에서 못 찾았을 때 침묵하지 말고 **찾지 못했다고 밝힌 뒤** 일반 지식으로 보충한다.
  밝히지 않고 보충하는 것이 가장 나쁘다.

## 컨텍스트를 늘리고 싶을 때

먼저 "이 질문에 답하는 데 정말 필요한가"를 묻는다. 매 질문마다 비용이 든다.
자료 전체를 보내는 방향의 변경은 하지 않는다. 필요하면 `StudyContextProvider` 의
구현을 바꾼다 — 인터페이스는 그러라고 있다.
