# session/repository — 에이전트 작업 규칙

## 지킬 것

- Spring Data 쿼리 메서드를 우선 쓴다. 이름으로 표현이 안 될 때만 `@Query`.
- 조회 결과가 없을 수 있으면 `Optional` 을 반환한다. `null` 을 반환하지 않는다.
- 존재 여부만 필요하면 `exists...` 를 쓴다. `find...().isPresent()` 로 대신하지 않는다.

## 하지 말 것

- Repository 에 비즈니스 로직 넣기 (조건 조합은 서비스의 몫)
- 네이티브 쿼리로 DB에 종속되는 코드 작성
- 다른 도메인의 엔티티를 여기서 조회
- `findAll()` 을 운영 코드에서 호출 (세션 수가 계속 늘어난다)
