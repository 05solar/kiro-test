# review — AI 에이전트 작업 규칙

## 절대 하지 말 것

- **AI 를 부르지 않는다.** 이 패키지에는 AI 클라이언트가 없고, 앞으로도 두지 않는다.
  정리 화면은 시험 직전에 여러 번 열어 보는 자리다. 열 때마다 요약을 생성하면
  볼 때마다 과금되고, 같은 내용이 매번 달라져 "정리"가 되지 않는다.
  요약이 부족하다고 느껴지면 **분석 단계**(`analysis`)를 고칠 일이지 여기가 아니다.
- **안 푼 문제의 정답을 담지 않는다.** `QuizReviewItemResponse.from` 이 그것을 걸러 준다.
  이 패키지에서 정답을 따로 채워 넣지 않는다. 이 응답과 `/quiz-review` 는 정답을 담는
  유일한 조회 경로라, 규칙이 무너지면 풀기 전에 정답을 보는 길이 열린다.
- **상태를 바꾸지 않는다.** 읽기 전용 패키지다. STEP 을 완료 처리하거나 답안을 저장하는
  코드를 넣지 않는다. 그 일은 `curriculum` 과 `quiz` 의 것이다.
- **다른 도메인이 이 패키지를 참조하게 하지 않는다.** 의존은 한 방향이다 —
  `review` 가 셋을 알고, 셋은 `review` 를 모른다.
- **회차를 합치지 않는다.** 마지막 회차만 담는다.
- **`SKIPPED` 를 미완료로 세지 않는다.** 완료 판정이 영영 참이 되지 않는다.
- 내부 예외 메시지를 응답에 담지 않는다.

## 판단이 필요할 때

- **완료 전에도 볼 수 있게 둔다.** `completed` 로 막지 않는다. 진행 중이어도 지금까지의
  정리는 볼 수 있어야 하고, 언제 열어 줄지는 화면이 정한다. 서버가 409 로 막으면
  화면이 "아직 안 끝났다"를 오류로 받게 된다.
- **점수 분모를 `quiz` 와 맞추지 않는다.** 여기는 푼 문제 기준, 그쪽은 전체 문제 기준이다.
  둘은 다른 질문에 답한다 — "얼마나 진행했나"와 "푼 것 중 얼마나 맞았나".
  같아 보인다고 하나로 합치지 않는다.
- **응답을 쪼개고 싶어지면** 먼저 화면이 몇 번 부르게 되는지 센다. 지금은 한 번이다.
  탭마다 부르게 만들면 탭을 옮길 때마다 기다린다.

## "틀린 문제만 다시 풀기" 에 API 를 만들지 않는다

요청을 받으면 만들고 싶어지겠지만, **만들지 않는 것이 설계다.**

답안은 최초 1회만 저장한다(`UNIQUE(session_id, quiz_id)`). 정답을 본 뒤 답을 고쳐
점수를 올릴 수 있으면 채점 기록이 성취도의 근거가 되지 못한다. 다시 풀기는 화면에서만
채점하는 연습이고, 저장할 것이 없으므로 엔드포인트도 없다.

같은 범위에서 **다른 문제**가 필요한 것이라면 그건 `POST /quizzes/regenerate` 다.
그쪽은 새 회차를 만들고 AI 를 부른다. 둘을 섞지 않는다.

## 새 필드를 더하고 싶을 때

이 패키지에는 엔티티도 마이그레이션도 없다. 정리에 없는 값이 필요하면
그 값을 가진 도메인에 더하고 여기서는 읽기만 한다. 여기에 테이블을 만들지 않는다.
